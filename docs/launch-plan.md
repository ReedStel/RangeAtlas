# Launch plan

GitHub Trending has no submission form or guaranteed placement. The goal of this plan is to earn
genuine attention by making RangeAtlas useful, understandable, and easy to evaluate.

## Repository readiness

- concise repository description and relevant lowercase topics;
- 1280×640 solid-background social preview;
- CI green on every supported Python version;
- a synthetic demo that runs in under one minute;
- tagged `v0.1.0` release with clear release notes;
- issue templates and a small, honest roadmap;
- no real captures, credentials, flags, or private environment details;
- RangeAtlas pinned alongside the strongest portfolio projects.

Suggested topics: `cybersecurity`, `cyber-range`, `python`, `nmap`, `wireshark`, `tshark`,
`burp-suite`, `metasploit`, `security-tools`, `vmware`, `kali-linux`, `network-security`,
`security-automation`, `blue-team`, `homelab`.

## Launch sequence

1. Merge the complete first release only after CI is green.
2. Publish `v0.1.0` and attach a repository ZIP plus a short demonstration clip.
3. Pin RangeAtlas and update the profile README with one outcome-focused sentence.
4. Post one honest technical walkthrough showing the problem, demo, safety boundary, and roadmap.
5. Share it only in communities where self-promotion is permitted and answer technical questions.
6. Convert recurring feedback into labelled issues and ship small follow-up releases.
7. Check GitHub Insights → Traffic for referrers, popular content, visitors, and clones.

## Do not do

- buy stars, followers, forks, or comments;
- trade stars in engagement groups;
- spam unrelated issues, pull requests, communities, or direct messages;
- inflate claims about users, deployments, vulnerabilities, or results;
- hide copied work or manufacture fake contributors.

Artificial engagement produces weak signals, damages credibility, and does not create users. A
smaller group of people who run the project, report issues, and return for releases is more valuable.

## Measures for the first month

- demo completion rate and setup questions;
- unique visitors and repository clones;
- stars from people outside the immediate network;
- useful issues or feature requests;
- returning contributors and release subscribers;
- referral sources that produce real engagement.
